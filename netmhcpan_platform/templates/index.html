💉 Multi-Epitope Vaccine Design Workflow v2.0 Core

Ranking peptides and designing a vaccine are different problems. A ranking table scores each peptide:HLA pair independently; a vaccine is a set, and what matters is how much of a population the set reaches together. TRIAD v2.0 adds that set-level layer with automated order optimization and construct safety audits.

1️⃣ State the target

In Predict Pipeline → Vaccine Design Target, choose the population and a coverage goal. “Auto-build panel” then picks the smallest set of high-frequency alleles that reaches it, so you never have to guess how many alleles to type in.

2️⃣ Pick into the basket

Tick peptides in the results table. The Epitope Set panel recomputes coverage on every click, lists the alleles the set still misses, and names the single best next pick.

3️⃣ Read ΔCov, not just rank

The ΔCov column is the percentage points a peptide would add on top of the basket. A Tier 1 peptide on an allele you already cover scores ~0; a Tier 2 peptide on an untouched allele can be worth several points.

4️⃣ Assemble and audit

Vaccine Designer joins the set with linkers (AAY, GPGPG, KK, EAAAK), reports length / GRAVY / pI, and scans every novel window across the joins for junctional epitopes before synthesis.

5️⃣ Optimize order & mRNA properties

Order Optimizer permutes epitope order to minimize off-target junctional binding hits, and exports FASTA, codon-optimized DNA, and CSV specifications with GC% and charge calculations.

📐 The coverage model

Individuals are drawn under Hardy–Weinberg equilibrium with the HLA-A / B / C loci independent. Writing P₀(T) for the probability that someone carries none of the alleles in T: 

P₀(T)   = ∏ over loci L of ( 1 − Σ f(a) for a ∈ T at locus L )²

≥1 hit  = 1 − P₀(R)                      R = alleles presenting ≥1 chosen peptide
≥2 hits = 1 − P₀(R) − Σ [ P₀(B_e) − P₀(R) ]   B_e = alleles presenting some peptide ≠ e

Both figures are computed exactly (no simulation), which is why they update instantly and never jitter between clicks. The ≥2 hits row is the redundancy a real vaccine needs: a person reached by only one epitope loses all protection if that allele is down-regulated or the epitope escapes, so a set whose ≥2 figure is far below its ≥1 figure is fragile no matter how good the headline number looks.

🗂️ Where the frequency tables come from

Every value is regenerated from one public input — the AFND snapshot mirrored at slowkow/allelefrequencies (MIT; AFND itself CC BY 4.0) — by tools/build_afnd_tables.py, which also re-verifies the shipped tables (python3 tools/build_afnd_tables.py --verify). Method: 2-field HLA-A/B/C records averaged by reported sample size n.

Taiwan is not one population. Its groups differ far too much to share a table: A*24:02 is 0.309 in the Minnan entries and 0.863 in the Paiwan ones, Saisiyat carry C*07:02 at 0.667 and B*39:01 at 0.549, and Tao carry B*15:25 at 0.400 where no other group does. Designing for one community against an island-wide average would misjudge every one of those, so each group is selectable in its own right and the island-wide table is reserved for island-wide programmes.

Why the island-wide table is blended, not pooled: AFND holds 11 recognised Indigenous entries (n = 693) against 6 Han-representative ones (n = 1,947), so averaging by sample size alone would give Indigenous peoples 26% of the table against roughly 2.5% of the island's population. A*24:02 runs at 0.633 in the Indigenous entries versus 0.167 in the Han ones, so a pooled average would report it at 0.2892 instead of 0.1785 — overstating the value of every A*24:02-restricted epitope by 62%. The blended table describes Taiwan as a whole; to design for one community, select that community in the dropdown rather than using the island-wide table.

⚠️ Changed in v1.2 — coverage numbers will differ from v1.1. Corrections: (a) AFND writes large sample sizes with thousands separators, and v1.1 parsed n with a plain float(), silently discarding every such record — 36.6% of rows and 99.0% of all sampled individuals, including the DKMS (n = 3,456,066) and NMDP (n = 1,242,890) registries. The World and Europe tables were built from the ~1% of the data with n < 1,000. Now fixed, which moves e.g. World A*02:01 from 0.1519 to 0.2393. With it fixed, pooled regions also require an allele to be reported by ≥ 3 populations, because one mis-entered record (AFND lists C*01:57 at 0.1996 in a single cohort and nowhere else) was otherwise enough to push a rare allele into the World top-18; (b) alleles at the same locus are now summed before the Hardy–Weinberg square rather than multiplied as independent events (v1.1 under-estimated within a locus); (c) alleles with no frequency record for the selected region now contribute 0 and are reported, instead of silently receiving a made-up 0.08 — so panel coverage is an explicit lower bound, and mouse H-2 runs no longer produce a meaningless “human population coverage”. The headline coverage pill now reports reachable coverage (what the predicted binders can actually present) rather than panel coverage, which never moved with the results.

🇹🇼 Taiwan is now 15 selectable populations. In v1.1 the Taiwan preset silently fell back to the East Asia table. It now has its own island-wide table plus every component group — Han, Minnan, Hakka, Indigenous, the 11 recognised peoples individually, and Pingpu. Against the island-wide table the key alleles shift appreciably from the old East Asia fallback: A*11:01 0.243 → 0.291, B*40:01 0.141 → 0.217, A*24:02 0.227 → 0.178 — and per-people they shift far more than that.
🐭 Preclinical Mouse H-2 Benchmark & Tumor Neoantigen Datasets v2.0 Core

TRIAD v2.0 integrates dedicated preclinical murine models (H-2) with species-aware anchor masking, inbred mouse strain presets (C57BL/6, BALB/c, C3H), and an extensive curated tumor neoantigen benchmark suite.

🐭 Species-Aware Mode Separation

Automatic toggling between Clinical Human (HLA-A/B/C) and Murine Preclinical (H-2-Kb, H-2-Db, H-2-Kd, H-2-Dd, H-2-Ld). Human population coverage is cleanly bypassed when evaluating mouse strains to prevent false coverage claims.

⚓ Murine Anchor Masking

Unlike human HLA which commonly anchors at p2 and pΩ, murine alleles employ distinct motif constraints (H-2-Kb: p5 and p8/p9; H-2-Db: p5 and p9). TCR contact scores accurately mask these anchor positions.

🔬 Curated Tumor Neoantigen Benchmark

Comprehensive benchmarking across 329+ experimentally validated murine tumor neoantigens from Smith 2019, Fernando 2019, and the prospective Capietto 2020 cohort (PMC7144530, N=216) with strict zero-leakage cross-validation.

📈 Empirical Biophysical Gold Standard

Multi-cohort prospective evaluations confirm NetMHCpan BA rank as the strongest single ranking indicator for in vivo murine CD8+ immunogenicity (AP 0.882 & 0.300), proving MHC binding stability is the paramount biological gatekeeper.

🎯 Composite Score (Composed Index) & Tier Decision Methodology

To prevent single-metric biases (such as selecting peptides that bind strongly but lack TCR contact features, or vice versa), TRIAD automatically computes a unified Composite Score (0.0000 ~ 1.0000) and assigns Clinical/Experimental Decision Tiers (Tier 1 / Tier 2 / Tier 3) for every predicted peptide:HLA pair.

🧮 4-Dimensional Normalized Weighting Formula:
Composite_Score = 0.40 × S_pres + 0.25 × S_aff + 0.25 × S_imm + 0.10 × S_breadth
• S_pres (40%): Presentation likelihood derived from %Rank_EL (≤0.5% maps to 0.75~1.0)
• S_aff (25%): Log-transformed IC50 binding affinity (1 - log10(IC50)/log10(50000))
• S_imm (25%): Calis et al. TCR contact physicochemical propensity ((Score + 0.4)/0.8)
• S_breadth (10%): Cross-HLA presentation ratio across all tested target alleles
🌟 Tier 1 (High Priority)
Criteria: %Rank_EL ≤ 0.5% (Strong Binder) AND Immunogenicity > 0 AND Composite Score ≥ 0.65
Interpretation: Top-priority validation targets. Confirmed high-probability native presentation combined with enriched aromatic/hydrophobic TCR contact residues for CD8+ T-cell activation.
⚡ Tier 2 (Secondary)
Criteria: %Rank_EL ≤ 2.0% (Weak Binder) AND Composite Score ≥ 0.45
Interpretation: Secondary candidate pool. Displays competent presentation propensity and moderate binding affinity; ideal for expanding epitope screening libraries.
🌐 Tier 3 (Low Priority)
Criteria: %Rank_EL > 2.0% OR lacks positive immunogenicity propensity
Interpretation: Low activation probability or borderline presentation; suitable as negative controls or backup candidates.

❓ Frequently Asked Questions (FAQ)
Q: Why are peptides constrained to 8–14 amino acids?
MHC Class I molecules possess closed peptide-binding grooves at both ends, restricting naturally presented epitopes to 8–14 residues (predominantly 9-mers). For intact proteins, switch to FASTA Format to allow the engine to automatically slide and digest into valid k-mers.
Q: How does the in-memory RAM Disk acceleration work?
All intermediate worker chunking and temporary IO pipelines write directly to Linux shared memory (/dev/shm/netmhc_tmp). This provides sub-millisecond IO throughput and automatically purges temporary data upon completion, ensuring zero physical SSD/HDD wear.
Q: Can I use patient-specific HLA typing?
Yes. You can search any HLA-A, HLA-B, or HLA-C 4-digit allele in the search box, or upload a custom text/CSV file containing your patient's typing under Regional Presets.
